## Audit (do not change API)

Source of truth: `RegisterCustomerRequestDto` + `CustomerAuthService.RegisterAsync` + `buildCustomerRegisterSchema` + `TenantPortalRegisterPage`.

API `CoreFields`: `name`, `email`, `password`, `phone`, `customerType`, `document`.  
Reserved keys (cannot be custom): those plus `confirmPassword`. Frontend also treats `cpf` as reserved (document for PF is copied into extras).

| Built-in (user-facing) | Key | Required? |
|---|---|---|
| Nome completo | name | yes (min 2) |
| E-mail | email | yes |
| Senha | password | yes (min 8) |
| Confirmar senha | confirmPassword | yes (FE only; not posted) |
| Celular | phone | yes (BR 10/11 digits) |
| Tipo de conta (PF/PJ) | customerType | yes |
| CPF ou CNPJ | document | yes (CPF if PF, CNPJ if PJ) |

**OPTIONAL_BUILT_IN_FIELDS:** none.

Previous copy (“nome, e-mail, senha e celular”) was incomplete — the config page must list all seven.

`PUT /api/registration-fields/{id}` already exists; `FieldKey` is **not** in the update DTO. Create still requires `fieldKey`.

**KEY_AUTOGENERATION_SAFE: YES** if:
- generate key only on **create** from display name (camelCase, strip accents, unique vs existing + reserved)
- **never** change a persisted key on edit
- still POST the same `fieldKey` string to the existing create contract

## Layout

`/configuracoes/cadastro` (`TenantRegistrationFieldsPage`): same shell as Pessoas e acesso — `mx-auto w-full max-w-6xl space-y-6`, centered title/subtitle (`max-w-xl text-center`). No extra padding (AppShell already pads).

`RegistrationFieldsManager` is also embedded in Super-Admin `TenantEditForm` — keep it usable there without duplicating the page H1.

### Campos padrão
Read-only rows: label + Obrigatório badge. Explanatory: “Estes campos fazem parte do cadastro padrão do portal.” No DTO names. No delete.

### Campos personalizados
Title + supporting text (no “ex.: CPF, foto…”). `+ Adicionar campo` (`Button size="sm"`). List saved rows: label, type **translated**, Obrigatório/Opcional badge, Editar/Excluir. Empty state like PeopleEmptyState pattern (local or reuse PeopleEmptyState only if it stays generic).

Create/edit in a **dialog**, not a permanent blank editor in the list.

## Editor
- Nome do campo (label)
- Tipo de campo — select shows translated labels, **value remains** `text|email|phone|cpf|cnpj|cep|boolean|number|select|photo|date`
- Campo obrigatório (checkbox)
- Select type: options CSV as today
- Key: autogenerated on create; do not edit on create/edit. Optional muted hint of derived key on create only.

Persist via existing create/update/delete. Add `updateRegistrationField` client for PUT (no new backend).
